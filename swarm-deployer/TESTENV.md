# Swarm Deployer — mock lab (TESTENV)

A throwaway lab that looks like production: a file server holding Build Packager zips, and a target server that is
a Docker Swarm manager reachable only over SSH, running three services (plus a registry), an SMB share on the same
release folder, and a mock self-hosted GitLab. Everything is a container named `sdtest-*` or a process with its pid
file in `$L`.

## 0. Safety rules (the host is a live swarm manager: fortress_*, demoapp)

- Never run `docker swarm|service|stack|node ...` against the host daemon. Swarm commands run only as
  `docker exec sdtest-target docker ...` (or over SSH into it). Test code uses one helper
  `tdocker(*args)` = `["docker", "exec", "sdtest-target", "docker", *args]`; a grep check fails the test run if any
  file under `testenv/` or `tests/` contains `docker service`, `docker swarm` or `docker stack` not preceded by
  `exec sdtest-`.
- Host-side docker use is limited to: `run/rm/build/exec/save/rmi/network/volume` on resources named `sdtest*`
  (containers, images `sdtest-*`/`sdtest/*`, network `sdtest-net`, volumes `sdtest-*`), plus read-only `ps`/`images`.
- dind never publishes its Docker API (no 2375/2376 port mapping). All published ports bind `127.0.0.1`.
- `down.sh` removes only `sdtest*` resources, by exact name or `name=sdtest` filter with a `^sdtest` re-check.
- Before/after snapshot: `testenv/host_snapshot.sh` writes `docker ps -a --format '{{.Names}} {{.Image}}'` minus
  `sdtest*` lines; the test run diffs the two (AC-3).
- The allowed host-docker commands also include: `run/rm` of container `sdtest-samba` (image `dperson/samba:latest`,
  already pulled); `save registry:2` piped into `docker exec -i sdtest-target docker load` (reads an existing host
  image); `build`, `save` and `rmi` of `sdtest-web3:*` images (the build_tar.sh-style check); `save busybox:latest` to
  `$L/gl-preload.tar` (Build Packager's `preload_tars` input `docker load`s it, which only re-tags an image already on
  the host).
- **Never put the literal text `docker service|swarm|stack|node ` anywhere in `testenv/` or `tests/`**, including
  comments, docstrings and the mock `.gitlab-ci.yml` that `seed.sh` writes. The `selftest.sh` grep rejects it.

## 2. File server `sdtest-files`

```
docker run -d --name sdtest-files -p 127.0.0.1:2222:22 \
  -v "$L/files/releases:/home/files/releases" \
  atmoz/sftp:latest files:sdtest-files-pass:1000
```
- uid 1000 = the host user, so host scripts and the FTP server can write the same folder. SFTP path seen by
  clients: `/releases` (atmoz chroots to `/home/files`).
- Build Packager uploads here with `remote_dir=/releases` (it creates subfolders if asked).
- FTP option (same files): `$L/venv/bin/python -m pyftpdlib -i 127.0.0.1 -p 2121 -r 30000-30009 -d "$L/files" -u files -P sdtest-files-pass -w`
  started in the background by `up.sh`, pid in `$L/ftp.pid`. FTP path is also `/releases`.
- FTPS option (same files, explicit TLS required for control and data):
  `$L/venv/bin/python testenv/ftps_server.py "$L/files" 2990 30010 files sdtest-files-pass "$L/keys/ftps.pem"`,
  started by `up.sh`, pid in `$L/ftps.pid`. The cert is self-signed (`CN=sdtest-ftps`), so the deployer's file
  server needs `verify_tls: false` (the default); `verify_tls: true` fails with `certificate verify failed`.
  Ports are in `lab.env` (`FTPS_PORT`, `FTPS_PASV`) and `env.json` (`file_server.ftps`).
- Actual ports may differ if a default was taken: `up.sh` picks the next free one; always read `lab.env`/`env.json`.

## 3. Target server `sdtest-target` (Docker-in-Docker + sshd + swarm)

`testenv/target/Dockerfile` (built on the host as `sdtest-target-img`; `docker:27-dind` is already pulled):
```dockerfile
FROM docker:27-dind
RUN apk add --no-cache openssh-server bash \
 && ssh-keygen -A \
 && (getent group docker || addgroup -S docker) \
 && adduser -D -s /bin/bash deploy && addgroup deploy docker \
 && echo 'deploy:sdtest-deploy-pass' | chpasswd \
 && sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication yes/' /etc/ssh/sshd_config \
 && mkdir -p /home/deploy/.ssh && chown deploy:deploy /home/deploy/.ssh && chmod 700 /home/deploy/.ssh
COPY entry.sh /entry.sh
ENV DOCKER_TLS_CERTDIR=""
ENTRYPOINT ["/entry.sh"]
```
`testenv/target/entry.sh`:
```sh
#!/bin/sh
set -e
[ -f /keys/sdtest_ed25519.pub ] && install -o deploy -g deploy -m 600 /keys/sdtest_ed25519.pub /home/deploy/.ssh/authorized_keys
/usr/sbin/sshd
exec dockerd-entrypoint.sh dockerd --host=unix:///var/run/docker.sock --group docker
```
Run (manager):
```
docker run -d --name sdtest-target --hostname sdtest-target --privileged --network sdtest-net \
  -v sdtest-target-docker:/var/lib/docker -v "$L/keys:/keys:ro" \
  -p 127.0.0.1:2223:22 -p 127.0.0.1:18081:8081 -p 127.0.0.1:18082:8082 -p 127.0.0.1:18083:8083 \
  sdtest-target-img
```
Then (inside, never on the host):
```
docker exec sdtest-target sh -c 'until docker info >/dev/null 2>&1; do sleep 1; done'
docker exec sdtest-target docker swarm init --advertise-addr eth0
```
- `deploy` is in group `docker` → `docker_cmd: "docker"` works without sudo. Key auth and password auth both work.
- The work dir `/home/deploy/sd-work` and backup dir `/home/deploy/sd-backups` are **not** pre-created (the
  deployer must create them).
- Published service ports use `mode=host` (no ingress mesh/IPVS needed inside dind, deterministic): service port
  8081 on the dind container → host `127.0.0.1:18081`.

Optional `sdtest-node2` (`up.sh --node2`): same image/volume pattern, `-p 127.0.0.1:2224:22`, joined as worker:
```
TOKEN=$(docker exec sdtest-target docker swarm join-token -q worker)
MIP=$(docker exec sdtest-target sh -c "ip -4 -o addr show eth0 | awk '{print \$4}' | cut -d/ -f1")
docker exec sdtest-node2 docker swarm join --token "$TOKEN" "$MIP:2377"
```
Port 2377 here is inside `sdtest-net` only (not published), so it does not clash with the host swarm.
Seeded services are constrained to `node.role==manager`, so node2 only proves "image loaded on extra nodes" and
serves as a "not a swarm manager" target for AC-6.

## 4. Mock services (git repos) `$L/repos/mock-web1`, `$L/repos/mock-web2`

Created by `seed.sh` with `git init -b main`, user `sdtest <sdtest@localhost>`. Five branches each:

| Branch | `/version` | Behaviour |
|---|---|---|
| `main` | `web1 v1` | healthy (used to seed the running v1) |
| `v2` | `web1 v2` | healthy |
| `broken` | — | container prints `web1 broken: exiting` and exits 1 after 1 s → swarm update fails → auto rollback |
| `unhealthy` | `web1 unhealthy` | serves `/version` but `/health` missing → HEALTHCHECK fails (and the health URL check fails) |
| `v3` | `web1 v3` | `v2` plus a root `deploy.yml` (`service: sdtest_web1`, `image: sdtest/web1`, `target: lab`, `health_url: http://127.0.0.1:8081/health`; web2 likewise). The other branches have no deploy.yml (Settings-mapping fallback). |

mock-web1 (busybox httpd), `Dockerfile`:
```dockerfile
FROM busybox:latest
COPY www /www
EXPOSE 8080
HEALTHCHECK --interval=2s --timeout=2s --start-period=2s --retries=3 CMD wget -q -O /dev/null http://127.0.0.1:8080/health || exit 1
CMD ["httpd", "-f", "-v", "-p", "8080", "-h", "/www"]
```
`www/version` = `web1 v1` (no trailing newline), `www/health` = `ok`. Branch `broken` replaces CMD with
`["sh", "-c", "echo 'web1 broken: exiting'; sleep 1; exit 1"]`. Branch `unhealthy` deletes `www/health`.

mock-web2 (nginx), `Dockerfile`:
```dockerfile
FROM nginx:1.27-alpine
COPY default.conf /etc/nginx/conf.d/default.conf
COPY www /usr/share/nginx/html
HEALTHCHECK --interval=2s --timeout=2s --start-period=2s --retries=3 CMD wget -q -O /dev/null http://127.0.0.1:8080/health || exit 1
```
`default.conf`: `server { listen 8080; location / { root /usr/share/nginx/html; default_type text/plain; } }`;
`www/version` = `web2 v1` / `web2 v2`; `www/health` = `ok`. Same `broken` / `unhealthy` branch pattern
(`broken`: `CMD ["sh","-c","echo 'web2 broken: exiting'; sleep 1; exit 1"]`).

Each repo also has a `README.md` so Build Packager's zip has realistic extra content.

## 5. Seeding (`seed.sh`, idempotent: resets services and packages)

1. **Base images into the target** (no network needed inside dind):
   `docker save busybox:latest nginx:1.27-alpine | docker exec -i sdtest-target docker load` (and into node2 if up).
2. **v1 images built inside the target** from the `main` branch:
   `git -C $L/repos/mock-web1 archive main | docker exec -i sdtest-target sh -c 'rm -rf /seed/web1 && mkdir -p /seed/web1 && tar -x -C /seed/web1'`,
   then `docker exec sdtest-target docker build -t sdtest/web1:v1 /seed/web1` (same for web2 → `sdtest/web2:v1`).
3. **Services** (inside the target; removed first if they exist):
   ```
   docker exec sdtest-target docker service rm sdtest_web1 sdtest_web2 sdtest_missing   # ignore errors
   docker exec sdtest-target docker service create --name sdtest_web1 --replicas 1 \
     --constraint node.role==manager --publish published=8081,target=8080,mode=host \
     --no-resolve-image --update-failure-action rollback --update-monitor 10s --detach=false sdtest/web1:v1
   docker exec sdtest-target docker service create --name sdtest_web2 ... published=8082 ... sdtest/web2:v1
   ```
   Then wait until `curl -fsS 127.0.0.1:18081/version` = `web1 v1` and `:18082` = `web2 v1` (timeout 60 s).
   Also removes `/home/deploy/sd-work`, `/home/deploy/sd-backups` and every `sdtest/*:backup-*` and
   `sdtest/*:2*` tag on the target, so each test starts from v1 with no backups.
4. **Packages on the file server** (Build Packager format, produced by `testenv/make_package.py` with the scratch
   venv's pyzipper, no Build Packager needed):
   `make_package.py --repo $L/repos/mock-web1 --branch v2 --service sdtest-web1 --password sdtest-zip-pass --out $L/files/releases`
   does: `git clone --depth 1 -b v2` into a temp dir → host `docker build -t sdtest-web1:<ts>` →
   `docker save -o <service>_<ts>/<service>_<ts>.tar` → host `docker rmi sdtest-web1:<ts>` → AES-256 zip with every
   entry under `<service>_<ts>/` (tar + the source folder `mock-web1/`) → `<service>_<ts>.zip`. Each call sleeps
   to get a unique second. Seeded set (recorded in `$L/packages.json`):

   | key | file | content |
   |---|---|---|
   | `web1_v1b` | `sdtest-web1_<t1>.zip` | main branch (older, to check sort) |
   | `web1_v2` | `sdtest-web1_<t2>.zip` | v2 |
   | `web1_broken` | `sdtest-web1_<t3>.zip` | broken |
   | `web1_unhealthy` | `sdtest-web1_<t4>.zip` (newest) | unhealthy |
   | `web2_v2` | `sdtest-web2_<t5>.zip` | web2 v2 |
   | `bad` | `sdtest-bad_<t6>.zip` | AES zip whose `.tar` is a plain tar without `manifest.json` |
   | `nomap` | `sdtest-nomap_<t7>.zip` | valid package with no mapping |
   | `archive_web1` | `archive/sdtest-web1_<t8>.zip` | in a subfolder (listing `dirs` + `path=`) |

   Plus `releases/README.txt` (appears in `other`). Tests pick packages by key from `packages.json`, never by "newest".
   The full seed also builds mock-web3 and pushes `127.0.0.1:5050/sdtest/web3:{v1,dev}`, and the reset recreates
   `sdtest_web3` (§8.5).
5. **Deployer config for tests**: `seed.sh` writes nothing into Swarm Deployer; tests configure it through the API
   (`PUT /api/config/file-server`, `POST /api/targets`, `PUT /api/mappings/...`) so the API is exercised too.
   Reference values:
   - file server: `sftp 127.0.0.1:2222 files / sdtest-files-pass, remote_dir /releases` (FTP: `ftp 127.0.0.1:2121`)
   - target `lab`: `127.0.0.1:2223 deploy`, key `$L/keys/sdtest_ed25519` (one test uses the password instead),
     `host_key_policy auto_add`, `work_dir /home/deploy/sd-work`, `backup_dir /home/deploy/sd-backups`
   - mappings: `sdtest-web1 → sdtest_web1, sdtest/web1, latest, http://127.0.0.1:8081/health`;
     `sdtest-web2 → sdtest_web2, sdtest/web2, latest, http://127.0.0.1:8082/health`;
     `sdtest-bad → sdtest_web1` (extract fails before the target is touched)
   - options: `converge_timeout 90`, `update_monitor 5`, `health_timeout 20`.

## 7. Test suites and phases

Run order (§12): `flock -o $L/lab.lock up.sh --node2` → `seed.sh` → `selftest.sh` → suites (each takes a host
snapshot before/after itself) → `down.sh`.

**Lab lock.** The lab is shared state, so every suite and `seed.sh` take an exclusive `flock` on `$L/lab.lock`
(`lab_lock()` in `tests/full_chain_test.py`, reused by `tests/ac_test.py`; `tests/ui_test.py` has its own copy).
A second suite waits until the first exits. A suite that holds the lock and calls `seed.sh` itself must export
`SDTEST_LAB_LOCK_HELD=1` (the `lab_lock()` helpers set it in `os.environ`, so child `seed.sh` runs inherit it);
otherwise `seed.sh` would wait on the lock its own parent holds. Never set it by hand while another suite runs.

Ports are picked the same way as the others: keep the existing container's or process's port, else use the default if it is free, else take the next free one.

- **`hostport()` [patch]** reads the binding with
  `docker inspect -f "{{(index (index .HostConfig.PortBindings \"$2/tcp\") 0).HostPort}}" "$1"` instead of `docker port`,
  which fails on a stopped container (after a host reboot `up.sh` aborted under `set -e`). One fix for every caller
  (`sdtest-files`, target, node2, samba).

### 8.1 Samba (`up.sh`, next to `sdtest-files`)

```bash
if ! running sdtest-samba; then
  docker rm -f sdtest-samba >/dev/null 2>&1 || true
  docker run -d --name sdtest-samba -p "127.0.0.1:$SMB_PORT:445" -v "$L/files/releases:/releases" \
    -e USERID="$(id -u)" -e GROUPID="$(id -g)" \
    dperson/samba:latest -r -u "$FILES_USER;$FILES_PASS" \
    -s "releases;/releases;yes;no;no;$FILES_USER" >/dev/null
fi
for i in $(seq 1 30); do   # docker-proxy binds the port before smbd is up: wait for a real SMB listing
  "$L/venv/bin/python" -c 'import sys, smbclient; smbclient.listdir(r"\\127.0.0.1\releases", port=int(sys.argv[1]), username=sys.argv[2], password=sys.argv[3])' \
    "$SMB_PORT" "$FILES_USER" "$FILES_PASS" >/dev/null 2>&1 && break; sleep 1
done
```

- `-r` turns off the recycle bin. Without it, SMB deletes leave a recycle folder in the shared folder, and SFTP and FTP list it.
- The image's `smb.conf` has `force user = smbuser` / `force group = smb` (checked in the image history), so **all**
  file I/O runs as `smbuser`. `USERID`/`GROUPID` make the image `usermod -o`/`groupmod -o` that user and group to
  `$(id -u)`/`$(id -g)` = 1000, so SMB writes land as uid 1000 in the 775 dir. `-u` carries **no** uid/gid fields
  (with them, `addgroup --gid 1000` clashes with the remapped `smb` gid and the user is never created).
- Do **not** use `-p` (chown of the share).
- SFTP, FTP and host checks therefore see the same file, at `/releases/<x>` over SFTP and `/<x>` inside the SMB share.
- The scratch venv must have `smbprotocol` before this block runs (§8.6 `up.sh` order).

**Endpoints:**

`<pid>` is a number or a URL-quoted path. Split the raw path on `/`, then `unquote` each part.

| method / path | behaviour |
|---|---|
| `GET /oauth/authorize` | Checks `client_id`, the `redirect_uri` regex, `response_type=code`, `code_challenge` and `code_challenge_method=S256`. A bad client or redirect returns 400 text. A missing PKCE returns 302 to `redirect_uri?error=invalid_request&state=…`. A `scope` with any word outside the app's registered `api` returns 302 to `redirect_uri?error=invalid_scope&state=…` (real GitLab does the same). Otherwise it stores the code (`challenge`, `redirect_uri`, `scope`, user) and returns 302 to `redirect_uri?code=<c>&state=<state>`. |
| `GET /avatar/<name>.png` | A fixed 1×1 PNG (`image/png`), so the TopBar `<img>` never logs a 404 console error. |
| `POST /oauth/token` (form) | `grant_type=authorization_code`: the code must exist and be unused, `redirect_uri` must be equal, `client_id` must be equal, `client_secret` must match if sent, and `b64url(sha256(code_verifier)) == challenge`. `grant_type=refresh_token`: the refresh token must be valid; both tokens are rotated. Either grant returns `{access_token, token_type: "Bearer", expires_in, refresh_token, scope, created_at}`. Errors return 400 `{"error": "invalid_grant"}`. |
| any `/api/v4/*` | Auth comes from `Authorization: Bearer <t>` or `PRIVATE-TOKEN: <t>`. Unknown or expired tokens return 401 `{"message": "401 Unauthorized"}`. |
| `GET /api/v4/user` | `{id, username, name, avatar_url, web_url}` |
| `GET /api/v4/projects` | The list of the three projects (query params are ignored). |
| `GET /api/v4/projects/<pid>` | The project, or 404 `{"message": "404 Project Not Found"}`. |
| `GET /api/v4/projects/<pid>/repository/branches` | From `git -C <repo> for-each-ref --format=%(refname:short) refs/heads`: `[{"name": b, "default": b == "main"}]` |
| `GET /api/v4/projects/<pid>/repository/files/<qpath>/raw?ref=<b>` | `git -C <repo> show <b>:<path>` as raw text, or 404 `{"message": "404 File Not Found"}`. |
| `GET /api/v4/projects/<pid>/variables`, `GET /api/v4/groups/<gid>/variables` | `[{key, value, variable_type, protected: false, masked, hidden, raw: false, environment_scope}]` (`value` is `null` for hidden ones). Needs the `api` scope, otherwise 403 `{"message": "403 Forbidden"}`. |
| `GET\|POST /<project path>.git/(info/refs\|git-upload-pack\|HEAD)` | **Smart HTTP** through `git http-backend` (CGI): `GIT_PROJECT_ROOT=$L/repos`, `PATH_INFO=/<repo dir>/.git/<rest>`, `GIT_HTTP_EXPORT_ALL=1`, plus `QUERY_STRING`, `REQUEST_METHOD`, `CONTENT_TYPE`, `CONTENT_LENGTH` and `HTTP_GIT_PROTOCOL`. The request body goes to stdin. Parse the CGI `Status:` header. Basic auth uses any username with a token that has `read_repository` or `api` as the password. With no or a bad auth header, return 401 `WWW-Authenticate: Basic realm="GitLab"`. `git-receive-pack` returns 403. |
| `GET /_mock/log` | Returns a JSON list of `{t, method, path, grant_type, user}`. Query strings are dropped, and the log never holds tokens, codes or verifiers. |
| `POST /_mock/ttl {"seconds": n}` | TTL for tokens issued from now on. |
| `POST /_mock/revoke` | Invalidates every OAuth access **and** refresh token issued so far (PATs stay), so the next refresh gets 400 `invalid_grant`. |
| `POST /_mock/reset` | Sets the TTL back to 7200 and clears the log. |

**Why smart HTTP and not dumb HTTP (D13 refinement):** Build Packager clones with `--depth 1`, and git rejects that over dumb HTTP with `fatal: dumb http transport does not support shallow capabilities`. A smart-HTTP prototype with this exact env was checked on this host: clone `--depth 1` works and a bad token gets `Authentication failed`.
